# Packaging

Distribution packaging for scia. Everything here is **ready to submit** but
nothing publishes automatically — cutting a tag builds the artifacts; getting
them into each package registry is a deliberate human step.

| Path | Channel | Generated or templated? |
| --- | --- | --- |
| (release CI) | Shell / PowerShell installers | generated by dist on every tag |
| (release CI) | Homebrew formula `scia.rb` | generated by dist as a release **artifact** (see below) |
| `winget/` | winget manifests (`rpschube.scia`) | in-repo templates; see `winget/README.md` |
| `aur/` | Arch AUR `PKGBUILD` | in-repo template; see `aur/README.md` |

The shell/PowerShell installers, per-artifact SHA-256 checksums, and the
Homebrew formula are all produced by `dist` from `dist-workspace.toml`; see
`docs/releasing.md`. Per-platform install instructions for end users live in
`docs/installing.md` and the README.

## Homebrew (human, after a release is published)

`dist` emits `scia.rb` as a downloadable release artifact. No Homebrew `tap` is
configured in `dist-workspace.toml`, so nothing is pushed automatically. To
publish:

1. Cut the release (`git tag vX.Y.Z && git push origin vX.Y.Z`) and wait for
   `release.yml` to attach `scia.rb` to the GitHub Release.
2. Create/refresh a tap repository named `homebrew-tap` under the `rpschube`
   account (users install from `rpschube/tap`).
3. Commit the released `scia.rb` into that tap (under `Formula/`).
4. Users then install with:
   ```
   brew install rpschube/tap/scia
   ```

To automate step 2–3 in a future release, set `tap = "rpschube/homebrew-tap"`
under `[dist]` in `dist-workspace.toml` and run `dist generate`; that adds a
publish job that pushes the formula on each tag. It is intentionally left off
so the first releases stay fully manual.
