# Releasing scia

The release workflow (`.github/workflows/release.yml`) is generated by
cargo-dist from `dist-workspace.toml`. Never hand-edit it — change behaviour in
`dist-workspace.toml` and run `dist generate` to regenerate.

Release builds never run on the dev machine; only tags build binaries, in CI.

## Procedure

1. Bump the workspace version in `Cargo.toml` (`[workspace.package] version`).
2. Run `just changelog vX.Y.Z` to regenerate `CHANGELOG.md`.
3. Commit `Cargo.toml`, `Cargo.lock` and `CHANGELOG.md` as
   `chore(release): vX.Y.Z` and merge it through the normal pull-request flow.
4. Tag the merge commit on `master`: `git tag vX.Y.Z && git push origin vX.Y.Z`.
5. The tag triggers `release.yml`, which builds every target, generates the
   installers and checksums, and publishes the GitHub Release.

`scia` and `scia-bridge` ship together from the same tag.

## Targets

- `x86_64-pc-windows-msvc`
- `x86_64-unknown-linux-gnu`
- `x86_64-unknown-linux-musl`
- `aarch64-apple-darwin`

## Installers and checksums

- Shell installer (`*-installer.sh`)
- PowerShell installer (`*-installer.ps1`)
- SHA-256 checksum alongside every artifact
